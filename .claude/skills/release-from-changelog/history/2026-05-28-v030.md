# release-from-changelog run — v0.3.0 second real invocation

## Context

Second production use of the skill. Cut v0.3.0 of OPOS itself — the same release that ships the FIX to the title-derivation bug exercised by v0.2.0's first invocation. Self-test of the fix on the very release that contains it.

## Inputs

- `version`: `v0.3.0`
- `target_branch`: `feat/company-os-framework`
- `repo`: `Koroqe/OPOS` (from `.claude/task-tracking.config.json`)

## What happened

1. Verified CHANGELOG entry exists: `grep -F "## [0.3.0]" CHANGELOG.md` matched.
2. Extracted via canonical awk pattern: 31 lines captured to `/tmp/release-notes-v0.3.0.md`.
3. Verified extract non-empty: `test -s` passed.
4. Verified no existing release (inverted exit-code): `if gh release view v0.3.0; then abort; fi` correctly did NOT abort.
5. **NEW title heuristic** (skips reserved Keep-a-Changelog names): scanned the entry, found `### Added` (reserved → skip), `### Changed` (reserved → skip), `### Notes` (reserved → skip). No non-reserved subheading. Title derived as empty → caller fell back to bare `v0.3.0`. **Exactly as designed.**
6. `gh release create v0.3.0 --repo Koroqe/OPOS --title "v0.3.0" --notes-file ... --target feat/company-os-framework` → `https://github.com/Koroqe/OPOS/releases/tag/v0.3.0`.
7. Verified creation: `gh release view v0.3.0 --json tagName --jq '.tagName'` returned `v0.3.0`.
8. **Step 8 (NOT in SKILL.md — workflow recovery, documented for next minor):** post-release scaffold smoke (`copier copy --vcs-ref v0.3.0 gh:Koroqe/OPOS ...`) revealed Copier was choking on `ui/templates/*.html.jinja` (treating them as templates to render with its own Jinja env, which lacks the `md` filter). Recovery: deleted the just-released v0.3.0 via `gh release delete v0.3.0 --cleanup-tag --yes`, committed a rename fix (`*.html.jinja` → `*.html`), pushed, re-cut v0.3.0 at the new HEAD. Final tag points to `b6f26a2`. Post-release scaffold verified working: SanityCo console boots at 200 + COMPANY_NAME substituted.

## Outcome

`success` — all six PROCESS.md success_criteria satisfied for the final cut. The skill's title-derivation fix is now self-validated on the release that contains it. The release-mid-flight recovery (delete + rename + re-cut) was a workflow gap surfaced for v0.4.0 (pre-release scaffold check).

- This is the **third** release cut via `release-from-changelog` (v0.2.0, v0.3.0). Each release has been a self-test: v0.2.0 surfaced the title bug; v0.3.0 fixed it AND surfaced the new pre-release-scaffold-check gap.
- The pre-validation via `ui/tests/test_title_heuristic.sh` (Slice 8 of this release) is the canonical pattern for skill changes going forward: PRE-test against synthetic fixtures BEFORE exercising on live releases. Should generalize to a `proposals/` folder pattern for any nontrivial skill change.
